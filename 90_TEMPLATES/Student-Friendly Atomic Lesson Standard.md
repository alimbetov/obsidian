# Student-Friendly Atomic Lesson Standard

## Назначение

Этот стандарт применяется к новым Java-урокам и при переработке старых notes. Он не упрощает техническую точность. Он уменьшает количество новых идей, которые ученик должен удерживать одновременно.

## Обязательная структура

### 1. Зачем это нужно

Одна жизненная или программная ситуация. Не начинай с определения из спецификации.

### 2. Простая модель

Не более трёх предложений. Используй знакомый образ, но сразу укажи границу аналогии.

### 3. Минимальный пример

Пример должен помещаться на одном экране и демонстрировать только один механизм.

### 4. Пошаговое выполнение

Таблица:

| Шаг | Что делает Java | Что изменилось |
|---:|---|---|
| 1 | | |

### 5. Точный механизм

Здесь вводятся официальные термины. Простая модель не должна заменять точное правило.

### 6. Сравнение

Минимум одна пара похожих конструкций:

```text
A похоже на B
но отличается по ...
```

### 7. Правдоподобная ошибка

Покажи неправильную модель, в которую действительно может поверить начинающий.

### 8. Самостоятельный прогноз

Ученик сначала записывает:

```text
compile / no compile
результат или exception
почему
```

Только затем открывает ответ или запускает код.

### 9. Лестница вопросов

1. Узнать термин.
2. Объяснить механизм.
3. Применить к новому коду.
4. Найти ошибку.
5. Спроектировать свой пример.

### 10. Продвинутый слой

Экзаменационная ловушка, production consequence и нормативная ссылка. Этот слой должен быть отделён от первого знакомства.

## Три уровня языка

### Уровень A — школьник

- короткие предложения;
- один новый термин за абзац;
- конкретный объект или действие;
- визуальная трассировка;
- отсутствие необъяснённых сокращений.

### Уровень B — студент

- точные определения;
- связи между механизмами;
- несколько вариантов решения;
- ограничения и trade-offs.

### Уровень C — собеседование и production

- границы версии;
- исключения из правила;
- диагностика;
- стоимость решения;
- связь с JVM, Spring или database.

## Что запрещено

- начинать урок с длинного списка терминов;
- использовать аналогию как доказательство;
- давать десять несвязанных примеров;
- скрывать ответ без механизма;
- писать «просто запомни» там, где можно вывести правило;
- считать правильный единичный ответ mastery;
- оценивать ученика словами «слабый» или «не понимает»;
- смешивать Java 17 и Java 21 без явной границы.

## Критерий готовности урока

Урок готов, если новый ученик может после него:

1. пересказать простую модель;
2. точно назвать механизм;
3. пройти трассировку;
4. решить новый пример;
5. объяснить типичную ошибку;
6. найти дальнейшую практику и proof.
